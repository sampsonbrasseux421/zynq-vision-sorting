# Vivado project

This directory contains the complete Vivado 2023.1 project, so that the design can
be opened and rebuilt without reconstructing anything by hand.

```
vivado/
├── yolo_hdmi.xpr              project file — open this
├── yolo_hdmi.srcs/
│   ├── constrs_1/new/camera_hdmi_pins.xdc    pin + clock constraints
│   ├── sources_1/new/                        top level, TMDS, servo PWM
│   ├── sources_1/bd/system/                  block design + 30 IP configs
│   ├── sources_1/ip/                         standalone IP (unused by the top)
│   ├── sources_1/imports/hdl/system_wrapper.v
│   └── sim_1/new/camera_hdmi_top_tb.v
├── scripts/                   build scripts (see below)
└── system.bit.bin             bitstream converted for fpga_manager
```

---

## 1. Open and build

```
File ▸ Open Project ▸ vivado/yolo_hdmi.xpr
```

Then **Generate Bitstream**. On a clean machine Vivado will regenerate the IP
output products first (a few minutes); synthesis and implementation take roughly
8 minutes on 8 threads.

Full figures for the committed bitstream:

| Metric | Value |
|---|---|
| Device | xc7z020clg400-2 |
| Slice LUTs | 9,213 (17.32 %) |
| Slice registers | 12,987 (12.21 %) |
| Block RAM | 5.5 (3.93 %) |
| DSP48E1 | 2 (0.91 %) |
| WNS at 50 MHz | +4.551 ns, TNS 0 |

The reports are committed as `build/utilization.rpt`,
`build/timing_summary.rpt` and `build/power.rpt`.

## 2. Rebuild from the command line

Run from the **repository root**:

```bash
vivado -mode batch -source vivado/scripts/rebuild.tcl
```

`rebuild.tcl` re-instantiates the custom `zdt_top8` module inside the block
design, regenerates the wrapper and runs synthesis plus implementation. It is the
script that produced the committed reports.

> The original working scripts used absolute Windows paths
> (`D:/pl_detector/rtl/...`). They are kept under `scripts/` for reference;
> `rebuild.tcl` is the portable version that resolves paths relative to the
> repository root.

## 3. Notes for anyone reusing this

| Point | Detail |
|---|---|
| IP versions | All IP is locked to Vivado 2023.1. Opening in 2025.2 or 2026.1 triggers an upgrade prompt — accept it and regenerate output products; no RTL changes are needed. |
| Block design | The custom logic sits in the BD as a *module reference* (`zdt_top8`, `video_osd_text21`). Vivado caches module-reference IP by module **name**, so if you edit that RTL in place you must either rename the module or delete and re-add the BD cell. |
| Unused IP | `sources_1/ip/` holds cordic / sqrt / multiplier / fifo IP from an earlier experiment. Nothing in the top level instantiates them, so they cost no resources, but they do slow down a rebuild. |
| Constraints | `camera_hdmi_pins.xdc` fixes the UART pins (K14/J14) and the servo PWM pin (N15) at LVCMOS33. Change here if you rewire. |
| Bitstream | `system.bit.bin` is the fpga_manager image. Regenerate it from a fresh `system.bit` with `bootgen -image build/bit_only.bif -arch zynq -process_bitstream bin`. |

---

## 4. What is not committed

| Excluded | Why |
|---|---|
| `.cache/`, `.gen/`, `.runs/` | 220 MB of regenerable build output |
| `*.dcp` checkpoints | Regenerated by synthesis |
| `system.bit` | 3.9 MB; regenerate locally. `system.bit.bin` is kept because it is what the board actually loads |
| Implementation logs of intermediate iterations | Superseded by the final reports in `build/` |
