# PL 硬件逆运动学 —— 最终报告素材

## 一、做了什么

把四轴机械臂的**逆运动学求解、角度→脉冲换算、四轴指令组帧**全部搬进 FPGA（Zynq-7020 的 PL 部分）。

**处理器的角色变成「报坐标」：写 3 个坐标寄存器 + 2 个控制字，然后等一个完成位。**

```
改动前：
  ARM 算逆解(libm, 4.8μs) → ARM 算脉冲 → ARM 写寄存器 → PL 组帧
  ↑ 每一步都受 OS 调度影响，抖动不可控

改动后：
  PS  写 X/Y/Z + 触发          （3 + 2 次寄存器写）
  PL  ① CORDIC 逆解            2.4 μs，抖动 0
      ② 角度 → 脉冲             4 个乘法器
      ③ 自动装载 POS（绝对模式）
      ④ 自动组帧 16 帧（12 使能 + 4 位置）
      ⑤ 广播同步
```

## 二、算法

与板卡上经现场标定的 `ik_zdt_pl` **完全等价**，参数取自 `/etc/ik.conf`：

```
LINK1=200  LINK2=175  BASE_H=112  TOOL_X=35  TOOL_Z=35
J2Z=-23040  J3Z=23040  J4Z=1280  ELBOW=-1
```

```
rr  = hypot(x, y)
dx  = rr − TOOL_X
dz  = z − (BASE_H − TOOL_Z)
c2  = (dx² + dz² − L1² − L2²) / (2·L1·L2)      限幅 [−1, 1]
th2 = ELBOW · acos(c2)
k1  = L1 + L2·cos(th2)
k2  = L2·sin(th2)                              ← ELBOW 影响此符号
th1 = atan2(dz, dx) − atan2(k2, k1)

j1 = atan2(y, x)·256/π + J1OFF
j2 = J2Z + th1·256/π
j3 = J3Z + th2·256/π
j4 = J4Z + (th1 + th2)·256/π
```

**ELBOW=−1 的实现要点**：`cos` 是偶函数不受影响，`sin` 是奇函数必须取反 ——
这一处最初漏掉，表现为 j2/j4 整体偏移一个常数。

## 三、硬件实现

| 模块 | 说明 |
|---|---|
| **CORDIC 向量模式** | 16 级迭代 + 预旋转 + 输出绕回，实现 atan2 |
| **整数开方** | 逐位逼近，16 拍，32 位输入 |
| **共享结构** | 一次求解复用同一 CORDIC 与开方单元，13 个阶段串行 |
| **角度→脉冲** | `pulse = (deg × PPR × 46603) >> 32`，用乘法代替除以 92160 |
| **自动触发** | CTRL bit5 = IK 自动模式，求解完成自动装载 POS 并组帧 |

定点格式：坐标 0.1 mm（s16），内部角度 Q16 弧度，输出 deg256（s32）。

## 五、调试过程中发现的三个真实问题

### 1. Vivado module_ref 的 RTL 快照缓存

Block Design 的 module reference 会把 RTL **快照**进
`*.gen/sources_1/bd/<bd>/ip/system_axi_<cell>_0/`。
修改底层 RTL 后，`reset_target` 与 `generate_target` **均不会重读源文件**，
必须更换模块名并重新 `create_bd_cell`。
本项目因此迭代了 `zdt_top8 → 9 → 10 → 12 → 13 → 14 → 15 → 16 → 17` 九个版本。

### 2. 验证脚本本身也需要被验证

板端 `devmem` 写入负数时会**静默失败**：`devmem 0x… 32 -1558`
实际写入 −1，却返回成功。导致连续三次 RTL 修改的验证结果完全相同，
一度误判为「综合未生效、逻辑被优化」。

修正为**显式写入补码 + 写入后回读核对**后，测试一次性全部通过。

> 教训：自动化验证必须先自证 —— 每次写入都要回读确认，
> 否则测的不是设计，而是脚本。

### 3. 多周期信号只拉高一拍

IK 自动模式最初用单拍脉冲 `ik_auto_req` 选择 POS：
第一帧拿到正确脉冲，之后退回旧寄存器值，后续 15 帧全部发错。
且因未强制绝对位置，相对模式下"全 0 脉冲"等于零增量 —— 表现为机械臂完全不动。

改为 **CTRL bit5 常驻选择 + 自动强制绝对模式**后正常。

## 七、笛卡尔直线插补 + S 曲线（扩展功能）

在逆解之上加了一级**笛卡尔空间直线插补**，使末端沿精确直线运动，速度按五次多项式 S 曲线平滑起停。

### 算法

```
每 50ms 一个插补节拍：
  u  = n / N                              N = 总时长 / 50ms
  s  = 10u³ − 15u⁴ + 6u⁵                  五次 S 曲线
  x  = x0 + (x1 − x0)·s                   y、z 同理
  → PL 逆解（第二个 ik_solver 实例）→ 角度转脉冲 → 发一帧位置
```

**为什么用五次多项式**：`s(0)=0, s(1)=1, s'(0)=s'(1)=0, s''(0)=s''(1)=0`
—— 首尾速度与加速度都为 0，没有冲击和残余振动。梯形速度曲线只有速度连续，加速度会突变。

### 验证

仿真（`tb_zdt_interp.v`）：

| 起终点 | 拍数 | 终点精度 | 共线误差 | 步长特征 |
|---|---|---|---|---|
| (250,0,150)→(280,0,120) | 10 | 精确 | 0 | 首13 / 最大5941 / 末13 |
| (200,100,120)→(200,−150,180) | 15 | 精确 | 0 | 首50 / 最大102346 / 末40 |
| (150,0,250)→(250,0,150) | 20 | 精确 | 0 | 首5 / 最大17485 / 末5 |

**共线误差 0 = 精确直线；首尾步长远小于中间 = S 曲线生效。**

上板验证：

| 时长 | 预期帧数 | 实测帧数 |
|---|---|---|
| 2000 ms（40 拍）| 160 | **160** |
| 3000 ms（60 拍）| 240 | **240** |
| 4000 ms（80 拍）| 320 | **320** |
| 5000 ms（100 拍）| 400 | **384**（运行中采样）|

帧数与节拍数严格对应，说明插补与组帧完全同步。

### 使用

```sh
pik X Y Z                # 点到点
pik -i X Y Z 3000        # 直线插补，3000ms
```
